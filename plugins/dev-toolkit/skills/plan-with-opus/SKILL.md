# プランニングフェーズは Opus（Fable）で行う

設計判断の質はプロジェクト全体のコストを左右するため、プランニングにはOpus/Fableクラス、実装にはSonnetを使う。既定モデルを `opusplan` にしておくと（`/model opusplan`、または settings.json の `"model"`）、**plan mode では Opus、実行では Sonnet** に自動で切り替わるため、plan mode に入るだけで本スキルの目的はほぼ達成される。

## 手順

1. **プランニング作業かを判定する**
   該当: アーキテクチャ設計、実装計画、仕様・要件定義、技術選定、セキュリティ監査、大規模リファクタの方針決定、トレードオフ比較。
   非該当: 判断済みの計画の実行、単純なバグ修正、定型作業（→ そのままSonnetで実行してよい）。

2. **メイン会話のモデルを確認する**
   - 現在のモデルが `opusplan` / `opus` / `fable` のいずれか → そのまま plan mode で計画を立てる（EnterPlanMode）。
   - `opusplan` のまま、かつ環境で `fable` が利用可能で、特に重い設計・監査タスクの場合は「`/model fable` への切替」を1回だけ提案してよい（禁止事項の「1タスク最大1回」ルールに従う。提案後は応答を待たず現行モデルで計画を続ける）。
   - それ以外（例: `sonnet` に手動変更されている）→ モデルはスキルからは切り替えられないため、**「設計判断の比重が大きいため `/model opusplan`（plan mode のみ Opus）への切替を推奨します」と一言だけ提案**し、ユーザーの応答を待たずに現行モデルで計画を続ける。

3. **計画立案をサブエージェントに委譲する場合**
   - `Plan` / `architect` 系エージェントに `model: "fable"`（model 候補に `fable` が無い環境では `"opus"`）+ `effort: "high"` を明示指定する。
   - 複数案の比較が必要なときは、視点の異なる計画案を並列生成し（例: リスク優先案 / MVP優先案）、判定役も同クラス（`fable` / `opus`）で行う。

4. **計画確定後は実装モードに戻す**
   - `opusplan` なら plan mode を抜けるだけで自動的に Sonnet に切り替わる。追加操作は不要。
   - 実装のサブエージェントには `model` を指定しない（セッションモデルを継承）。

## 根拠（参照URL）

- `opusplan`: plan mode で Opus、実行で Sonnet に自動切替する公式モデル設定 — https://code.claude.com/docs/en/model-config
- モデル別コスト最適化（Opusは計画・Sonnetは実装が費用対効果最良）— https://code.claude.com/docs/en/costs

## 禁止事項

- ユーザーが明示的にモデルを指定している場合の上書き提案（ユーザー指定を常に優先）
- モデル切替提案の連発（1タスクにつき最大1回）
